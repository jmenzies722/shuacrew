## 1. @anthropic-ai/claude-agent-sdk — **0.3.281**

- ESM only (`"type":"module"`), Node >=18. Peer deps: `@anthropic-ai/sdk >=0.93.0`, `@modelcontextprotocol/sdk ^1.29.0`, `zod ^4`.
- Ships a **native Claude Code binary** through platform optionalDependencies (`@anthropic-ai/claude-agent-sdk-darwin-arm64` etc.).
  `npm ci --omit=optional` means no binary. In that case set `pathToClaudeCodeExecutable` (for example the local `claude` 2.1.280).
- Docs: https://code.claude.com/docs/en/agent-sdk/overview, /quickstart, /typescript. Changelog: github.com/anthropics/claude-agent-sdk-typescript

### query()
```ts
function query(p: { prompt: string | AsyncIterable<SDKUserMessage>; options?: Options }): Query
interface Query extends AsyncGenerator<SDKMessage, void> {
  interrupt(); setPermissionMode(m); setModel(m?); setMaxThinkingTokens(n);
  streamInput(AsyncIterable<SDKUserMessage>); rewindFiles(userMessageId, {dryRun?}): Promise<RewindFilesResult>;
  supportedModels(); supportedAgents(); supportedCommands(); mcpServerStatus(); setMcpServers(); accountInfo();
  getContextUsage({detail?}); stopTask(taskId); initializationResult(); close();
  usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET({skipBehaviors?})  // plan 5h/7d windows (see auth)
}
```
Other top-level exports: `listSessions, getSessionInfo, getSessionMessages, getSubagentMessages, listSubagents, forkSession(id), renameSession, tagSession, deleteSession, createSdkMcpServer, tool(name, desc, zodShape, handler), resolveSettings, startup`.
Use `prompt` as an AsyncIterable (streaming input mode) to get a long-lived multi-turn session that `canUseTool`, `interrupt()` and `streamInput` all work on.

### Auth behaviour
- The SDK spawns the Claude Code binary, which resolves credentials like the CLI does: `ANTHROPIC_API_KEY` (env) / apiKeyHelper, then `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`),
  then the logged-in claude.ai OAuth credential (macOS Keychain), then Bedrock/Vertex/Foundry via `CLAUDE_CODE_USE_*`. `system/init.apiKeySource` reports the source:
  `'ANTHROPIC_API_KEY'|'apiKeyHelper'|'/login managed key'|'none'`. The docs say `'none'` means "claude.ai OAuth login, a bearer token, or 3P".
- **So yes: with no `ANTHROPIC_API_KEY` on a machine where `claude` is logged in, it runs on the Pro/Max subscription** [inferred from the types and shared binary. Not live-tested].
  Signals that this is happening: `apiKeySource:'none'`, `rate_limit_event` messages (typed "for claude.ai subscription users"), `usage_*().rate_limits_available=true`,
  and `subscription_type` ('pro'|'max'|'team'|'enterprise'). Because `env` replaces the environment, build it without `ANTHROPIC_API_KEY` to force subscription use.
- **Policy caveat (docs, quickstart and overview):** "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate
  limits for their products, including agents built on the Claude Agent SDK." A personal tool running on your own login is outside "offering to others", but do
  not ship ShuaCrew to other people with subscription login.
- Usage limits show up as: `rate_limit_event` with `status:'rejected'` and `resetsAt`; an assistant message with `error:'rate_limit'` (also `billing_error`,
  `authentication_failed`, `overloaded`); `system/api_retry` while retrying; finally a `result` with `is_error:true` (and `api_error_status` 429).

### Minimal TS
```ts
import { query, type SDKMessage } from '@anthropic-ai/claude-agent-sdk';
const ac = new AbortController();
const { ANTHROPIC_API_KEY: _drop, ...env } = process.env;           // force subscription auth
const q = query({ prompt: 'Summarise README.md', options: {
  cwd: '/path/repo', model: 'opus', permissionMode: 'default', abortController: ac, env,
  settingSources: ['project'], includePartialMessages: true, enableFileCheckpointing: true, maxTurns: 30,
  canUseTool: async (tool, input, { signal }) =>
    tool === 'Bash' ? { behavior: 'deny', message: 'no shell' } : { behavior: 'allow', updatedInput: input },
  hooks: { PreToolUse: [{ matcher: 'Edit|Write', hooks: [async (i) => ({ hookSpecificOutput: { hookEventName: 'PreToolUse', permissionDecision: 'ask' } })] }] },
  agents: { reviewer: { description: 'Reviews diffs', prompt: 'You review code.', tools: ['Read', 'Grep'] } },
}});
for await (const m of q) {
  if (m.type === 'system' && m.subtype === 'init') console.log('session', m.session_id, m.apiKeySource);
  else if (m.type === 'rate_limit_event') console.log(m.rate_limit_info);
  else if (m.type === 'result') console.log(m.subtype, m.total_cost_usd, m.usage);
}
```

## 2. Codex app-server (local codex-cli 0.154.0; npm `@openai/codex` 0.156.1)

Docs: https://learn.chatgpt.com/docs/app-server (redirected from developers.openai.com/codex/app-server). Source: github.com/openai/codex/tree/main/codex-rs/app-server.
CLI: `codex app-server [--listen stdio://|unix://PATH|ws://IP:PORT] [-c key=value] [--enable F]`; subcommands `daemon`, `proxy`, `generate-ts`, `generate-json-schema` (all marked "[experimental]").

### Wire
- stdio (default): **newline-delimited JSON (JSONL)**, JSON-RPC 2.0 semantics **with `"jsonrpc":"2.0"` omitted on the wire**. The WebSocket transport is "experimental and unsupported".
- Handshake: request `initialize` → then notification `initialized`. Any request before that gets a "Not initialized" error.
```json
{"method":"initialize","id":0,"params":{"clientInfo":{"name":"shuacrew","title":"ShuaCrew","version":"0.1.0"},"capabilities":{"experimentalApi":true}}}
{"method":"initialized","params":{}}
```
  InitializeResponse: `{userAgent, codexHome, platformFamily, platformOs}`. Some methods (`thread/turns/list`, `thread/items/list`, `process/*`) need `experimentalApi:true`.

### Client→server methods (from generated ClientRequest.ts; 100+ total)
- Threads: `thread/start`, `thread/resume`, `thread/fork`, `thread/read`, `thread/list`, `thread/loaded/list`, `thread/archive`,
  `thread/unarchive`, `thread/delete`, `thread/rollback`, `thread/revert`, `thread/compact/start`, `thread/name/set`, `thread/shellCommand`, `thread/unsubscribe`
- Turns: **`turn/start`**, `turn/steer` (inject input into a running turn), **`turn/interrupt` `{threadId, turnId}`**, `review/start`
- Account: `account/read`, `account/login/start`, `account/login/cancel`, `account/logout`, **`account/rateLimits/read`**, `account/usage/read`, `getAuthStatus`
- Misc: `model/list`, `config/read`, `config/value/write`, `skills/list`, `hooks/list`, `mcpServerStatus/list`, `command/exec`, `fs/*`, `fuzzyFileSearch`, `gitDiffToRemote`

`ThreadStartParams`: `{model?, modelProvider?, serviceTier?, cwd?, approvalPolicy?: AskForApproval, approvalsReviewer?, sandbox?: SandboxMode, config?: Record<string,Json>, baseInstructions?, developerInstructions?, personality?, ephemeral?, …}`
→ `{thread: Thread /*id, sessionId, model, cwd, status, path…*/, model, modelProvider, cwd, approvalPolicy, sandbox: SandboxPolicy, reasoningEffort}`.
`ThreadResumeParams`: `{threadId, …same overrides…, excludeTurns?}`.
`TurnStartParams`: `{threadId, input: UserInput[], cwd?, approvalPolicy?, sandboxPolicy?: SandboxPolicy, model?, effort?: ReasoningEffort(string), summary?, personality?, outputSchema?, clientUserMessageId?}` → `{turn: Turn}`.
`UserInput`: `{type:'text', text, text_elements:[]} | {type:'image', url} | {type:'localImage', path} | {type:'skill'|'mention', name, path} | …`.
- `AskForApproval` = `"untrusted" | "on-request" | "never" | {granular:{sandbox_approval, rules, skill_approval, request_permissions, mcp_elicitations}}`
- `SandboxMode` (thread-level) = `"read-only" | "workspace-write" | "danger-full-access"`. JSON schema confirms kebab-case. The docs example shows `"workspaceWrite"`, but trust the schema.
- `SandboxPolicy` (turn-level) = `{type:'readOnly', networkAccess} | {type:'workspaceWrite', writableRoots, networkAccess, excludeTmpdirEnvVar, excludeSlashTmp} | {type:'dangerFullAccess'} | {type:'externalSandbox', networkAccess}`

### Server→client notifications (ServerNotification.ts, key subset)
`thread/started`, `thread/status/changed`, `turn/started`, **`turn/completed` `{threadId, turn:{id, items, status:'completed'|'interrupted'|'failed'|'inProgress', error, durationMs}}`**,
**`item/started` / `item/completed` `{item: ThreadItem, threadId, turnId}`**, **`item/agentMessage/delta` `{threadId, turnId, itemId, delta}`**,
`item/reasoning/summaryTextDelta`, `item/reasoning/textDelta`, `item/commandExecution/outputDelta`, `item/fileChange/outputDelta`, `item/fileChange/patchUpdated`,
`turn/diff/updated`, `turn/plan/updated`, `item/plan/delta`, `item/mcpToolCall/progress`, `serverRequest/resolved`,
**`thread/tokenUsage/updated` `{threadId, turnId, tokenUsage:{total, last:{totalTokens,inputTokens,cachedInputTokens,cacheWriteInputTokens,outputTokens,reasoningOutputTokens}, modelContextWindow}}`**,
**`account/rateLimits/updated` `{rateLimits: RateLimitSnapshot}`**, `error` `{error: TurnError, willRetry, threadId, turnId}`, `thread/compacted`, `model/rerouted`, `warning`, `account/updated`, `account/login/completed`.
ThreadItem `type`s: userMessage, agentMessage, reasoning, plan, commandExecution (`command, cwd, status, aggregatedOutput, exitCode`), fileChange (`changes, status`),
mcpToolCall, dynamicToolCall, collabAgentToolCall, subAgentActivity, webSearch, imageView, contextCompaction, enteredReviewMode/exitedReviewMode, hookPrompt, functionCallOutput.

### Approvals (server→client JSON-RPC *requests*; reply with the same `id`)
- `item/commandExecution/requestApproval` params `{kind, threadId, turnId, itemId, startedAtMs, approvalId?, reason?, command?, cwd?, commandActions?, proposedExecpolicyAmendment?, networkApprovalContext?}`
  → result `{decision: "accept" | "acceptForSession" | "decline" | "cancel" | {acceptWithExecpolicyAmendment:{execpolicy_amendment}} | {applyNetworkPolicyAmendment:{…}}}`
- `item/fileChange/requestApproval` params `{threadId, turnId, itemId, startedAtMs, reason?, grantRoot?}` → `{decision: "accept"|"acceptForSession"|"decline"|"cancel"}`
- Also: `item/permissions/requestApproval`, `item/tool/requestUserInput`, `mcpServer/elicitation/request`, `item/tool/call` (dynamic tools), `account/chatgptAuthTokens/refresh`.
  The legacy v1 requests `execCommandApproval` / `applyPatchApproval` still exist, but use the v2 `item/*` ones.

### Auth and usage limits
- The app-server uses the CLI's stored login in `$CODEX_HOME` (default `~/.codex`, returned as `codexHome`). `account/read` → `{account: {type:'chatgpt', email, planType} | {type:'apiKey'} | {type:'amazonBedrock',…} | null, requiresOpenaiAuth}`.
  If logged out: `account/login/start` `{type:'chatgpt'}` (browser flow, then `account/login/completed`), or `{type:'chatgptDeviceCode'}`, or `{type:'apiKey', apiKey}`, or `{type:'chatgptAuthTokens', accessToken, chatgptAccountId}` (host-managed tokens, refreshed via the server request `account/chatgptAuthTokens/refresh`).
  Running `codex login` once is enough; ShuaCrew should never touch auth.json.
- Limits: `account/rateLimits/read` → `{rateLimits: {primary/secondary: {usedPercent, windowDurationMins, resetsAt}, credits, planType, rateLimitReachedType, …}, rateLimitsByLimitId, ordinaryUsageAllowed}`,
  pushed as `account/rateLimits/updated`. A hit limit surfaces as `error` notification / `turn.error.codexErrorInfo` = **`"usageLimitExceeded"`** (also `"rateLimitExceeded"`, `"serverOverloaded"`, `"unauthorized"`, `"contextWindowExceeded"`),
  and the turn ends with `status:'failed'`. The WS transport can also return JSON-RPC error `-32001` "Server overloaded; retry later".
- Version skew: regenerate the types with `codex app-server generate-ts --out <dir>` against the installed binary. Do not hand-maintain them (they are generated by ts-rs).

### Fallback: @openai/codex-sdk **0.156.1** (depends on `@openai/codex` 0.156.1; spawns `codex exec --experimental-json`)

## 3. Agent Client Protocol (TS)

- **Package: `@agentclientprotocol/sdk` 1.5.0** (published 2026-09-21; repo github.com/agentclientprotocol/typescript-sdk; docs agentclientprotocol.com).
  `@zed-industries/agent-client-protocol` (0.4.5) is **deprecated**: "renamed to @agentclientprotocol/sdk". `PROTOCOL_VERSION = 1`. Subpaths: `./experimental/v2`, http/ws stream helpers.
- Transport helper: `ndJsonStream(writable: WritableStream<Uint8Array>, readable: ReadableStream<Uint8Array>)` (newline-delimited JSON-RPC over the child's stdio).
- **In 1.5 `ClientSideConnection` is `@deprecated`** in favour of the `client()` builder. Both work:
```ts
import * as acp from '@agentclientprotocol/sdk';
import { spawn } from 'node:child_process'; import { Readable, Writable } from 'node:stream';
const p = spawn('kiro-cli', ['acp'], { stdio: ['pipe','pipe','inherit'] });
const stream = acp.ndJsonStream(Writable.toWeb(p.stdin), Readable.toWeb(p.stdout));
// New style:
const res = await acp.client({ name: 'shuacrew' })
  .onRequest(acp.methods.client.session.requestPermission, (ctx) => ({ outcome: { outcome: 'selected', optionId: ctx.params.options[0].optionId } }))
  .connectWith(stream, async (ctx) => {
    await ctx.request(acp.methods.agent.initialize, { protocolVersion: acp.PROTOCOL_VERSION, clientCapabilities: { fs: { readTextFile: true, writeTextFile: true } } });
    return ctx.buildSession(process.cwd()).withSession(async (s) => {
      s.prompt('Hello');
      for (;;) { const m = await s.nextUpdate(); if (m.kind === 'stop') return m.response; /* m.notification.update */ }
    });
  });
// Legacy style (deprecated, still exported):
const conn = new acp.ClientSideConnection((_agent) => ({ requestPermission: async (p) => ({ outcome: { outcome: 'cancelled' } }), sessionUpdate: async (n) => {} }), stream);
await conn.initialize({ protocolVersion: acp.PROTOCOL_VERSION, clientCapabilities: {} });
const { sessionId } = await conn.newSession({ cwd: '/abs/path', mcpServers: [] });
const { stopReason, usage } = await conn.prompt({ sessionId, prompt: [{ type: 'text', text: 'hi' }] });
```
- Agent methods: `initialize, newSession({cwd, mcpServers, additionalDirectories?}), loadSession, resumeSession, listSessions, closeSession, deleteSession, setSessionMode, setSessionConfigOption, authenticate, logout, prompt({sessionId, prompt: ContentBlock[]}), cancel({sessionId})`.
  `PromptResponse = {stopReason: 'end_turn'|'max_tokens'|'max_turn_requests'|'refusal'|'cancelled', usage?}`.
- Client handlers: `requestPermission`, `sessionUpdate` (required); `readTextFile`, `writeTextFile`, `createTerminal`, `terminalOutput`, `waitForTerminalExit`, `killTerminal`, `releaseTerminal`, `createElicitation` (optional).
- `session/update` kinds (`update.sessionUpdate`): `user_message_chunk, agent_message_chunk, agent_thought_chunk, tool_call, tool_call_update, plan, plan_update, plan_removed,
  available_commands_update, current_mode_update, config_option_update, session_info_update, usage_update {used, size, cost?}, compaction_update, compaction_summary_chunk, notice`.
  ToolCall status: `pending|in_progress|completed|failed`. ToolKind: `read|edit|delete|move|search|execute|think|fetch|switch_mode|other`.
- `requestPermission` params `{sessionId, toolCall: ToolCallUpdate, options: {optionId, name, kind:'allow_once'|'allow_always'|'reject_once'|'reject_always'}[]}` → `{outcome: {outcome:'selected', optionId} | {outcome:'cancelled'}}`.

**kiro-cli 2.23.1 supports ACP**: `kiro-cli acp [--agent NAME] [--model ID] [--effort low..max] [-a|--trust-all-tools] [--trust-tools T,..] [--agent-engine v1|v2|v3 (default v2)] [--auth-method cli]`.
It uses the Kiro login already stored by `kiro-cli login`. (`kiro-cli crew` also exists: "Launch Kiro Crew".) Note: the memory says the day-job Kiro is sealed, so only point this at personal Kiro auth.

### SQLite driver decision: **better-sqlite3 13.0.3 + drizzle-orm 0.45.3 (`drizzle-orm/better-sqlite3`)**
- better-sqlite3 13 moved to **node-addon-api (N-API, ABI-stable)**, `engines: node >=22`, no install script, and it **ships `prebuilds/darwin-arm64.node` inside the tarball**.
  Verified: it loads on **Node v25.9.0 (ABI 141)**, SQLite 3.53.4, and `sqliteVec.load(db)` works (`vec_version()` = v0.1.9). No node-gyp is needed.
- `node:sqlite` in Node 25: `DatabaseSync` is **Stability 1.2 Release candidate since v25.7.0** (https://nodejs.org/docs/latest-v25.x/api/sqlite.html), with no warning on 25.9.
  sqlite-vec also loads through it (`new DatabaseSync(p, {allowExtension:true})`, verified). **But drizzle-orm's stable 0.45.3 has no node-sqlite driver.** It only exists in
  `drizzle-orm@1.0.0-rc.4` (`drizzle-orm/node-sqlite`), and that is an RC.
- Recommendation: use better-sqlite3 now (stable drizzle, mature, prebuilt for Node 25). Keep the DB module behind a small interface so it can switch to `node:sqlite`
  once drizzle 1.0 is GA and node:sqlite reaches Stability 2.
