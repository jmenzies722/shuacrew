# Shared visual teaching

User-supplied implementation brief: question/reference → existing subscription runtime → validated semantic patch → shared vector lesson → identity-preserving follow-up. Main Mac workspace and companion share the same gateway state, including selection, step and revision. No new authentication, model-generated drawing code, commits or pushes.

## Design
- Core v1 Zod contract: source records, steps with citations/assumptions, stable semantic objects and connectors, create/update/delete/highlight/focus operations, session and base revision. All patches validate against a cloned document before atomic persistence. User-edited objects are protected from model updates/deletion. Undo/redo restores content with monotonically increasing revision.
- Gateway owns sessions and active session pointer in a private atomic JSON store. Mutation revisions prevent racing clients; in-flight generation has cancellation and stale-result rejection. Polling synchronizes both surfaces without introducing a second lesson owner. Save/load selects persisted sessions; explicit export/import validates documents.
- Existing Claude SDK native JSON-schema output, tools disabled, existing subscription environment. Installed Codex protocol has outputSchema and typed image input, but a tool-free teaching adapter is not wired in this increment: teaching requires Claude; Codex/local remain selectable for ordinary companion chat. No image generation API, no new speech API. Images supplied as typed image blocks, not fabricated file reads. Text/document sources are literal reference data; scanned documents require vision or a clear unsupported message.
- SVG canvas renders only known primitives. Application measures/wraps text and lays out graph layers, routes labeled connectors around node boxes, with separate groups/callouts/text. Canvas world coordinates never mean screen coordinates. Pan/zoom/fit, object selection/label/position edits, undo/redo; narration step selects/highlights objects and progressive visibility.
- Native overlay accepts only capture-bound normalized annotations. Capture record includes UUID, CGDisplayID, pixel size/crop, display frame, timestamp and context generation. Mapping explicitly converts image pixels/crop to display points with Y inversion. Non-activating click-through panels; clear/dismiss via companion plus Escape. Invalidate on input, app activation, display changes, expiration and new capture. Never restore annotations from saved lessons without a fresh capture.
- Runtime teaching prompt: answer first, sources and assumptions, one concept/step, simpler/deeper/example, preserve stable IDs/user edits, no claims of app actions without capability acknowledgements. Conceptual floor plans only without dimensions and domain requirements.
- Companion gains an explicit Auto/provider/model picker; unavailable choices report a reason instead of silently switching. Teaching and ordinary chat use the same preference.

## Verification
Contract/atomicity/stale/undo/persistence/cancellation and transform tests; real logged-in SDK smoke question then follow-up; native UI short/long/crowded diagrams, theme checks. Multi-display hardware and unsupported input formats are reported honestly. No model call executes arbitrary shell/drawing code. Existing worktree changes preserved.

## Persistent guided practice
Explicit Start authorizes click observations on the selected display while active. The native observer records click coordinates and a fresh post-click capture, never keystroke text. Debouncing coalesces rapid input; a bounded queue cancels superseded checks. Claude receives the current goal, previous feedback and fresh capture through existing typed image input. A separate validated assessment references the exact event and step, with visible evidence, retry/uncertain/verified outcomes and optional capture-bound hints. Wrong attempts never advance or end the lesson. Pause/Escape stops observation and cancels pending verification; a native heartbeat prevents detached views from silently continuing. Restarts preserve the goal and feedback but require an explicit Resume before observing again. Active guidance feedback remains available in the companion.
